01 / LIVE OPERATION

라이브 송출은 네 가지 업무가 연결됩니다

촬영만 맡기는 것과 실시간 화면을 제작해 온라인 플랫폼으로 송출하는 일은 다릅니다. 현장 장비와 플랫폼, 담당자의 업무를 구분해 견적 범위를 확인하세요.

01 / 입력 소스

카메라·PPT·현장 영상

발표자 카메라, 객석·무대 전경, 발표자료 노트북, 오프닝 영상, 원격 발표자 화면 등 실제 송출에 필요한 화면 소스를 정합니다.

확인 자료: 화면 소스 목록 · 무대 동선 · 필요한 화면 구성
02 / 오디오

현장과 시청자 음향 분리

현장 PA와 온라인 송출에 필요한 음성을 구분해 마이크, 영상 속 소리, 화상회의 원격 연자의 음성 경로를 구성합니다. 온라인 시청자 기기에서 실제 청취 테스트를 합니다.

확인 자료: 믹서 출력·입력 · 현장 스피커 · 플랫폼 오디오
03 / 인코딩·플랫폼

화면 전환과 온라인 운영

카메라·PPT·자막·대기 화면을 큐시트에 맞춰 전환하고, 인코더와 인터넷 회선을 통해 플랫폼으로 전송합니다. 계정 권한·공개 설정·실시간 채팅 담당을 사전에 확인합니다.

확인 자료: 전환 큐시트 · 인코더·회선 · 플랫폼 관리자
04 / 모니터링·기록

시청자 화면과 녹화본 관리

실제 수신 화면·음량·지연, 온라인 질문을 확인하고 송출 종료까지 모니터링합니다. 현장 촬영 원본과 송출 프로그램 출력, 편집용 녹화 파일의 인수 범위는 구분합니다.

확인 자료: 모니터링 기준 · 장애 연락망 · 녹화·납품 목록
02 / SIGNAL PATH

송출 신호는 이 경로로 전달됩니다

어느 지점에서 화면·음향이 끊겼는지 확인할 수 있어야 장애에 대응할 수 있습니다. 아래는 구성을 이해하기 위한 일반적인 흐름이며 실제 장비 연결은 행사장 조건에 따라 달라집니다.

01 / SOURCE

카메라·발표자료

무대 카메라, PPT 노트북, 오프닝 영상, 원격 발표자

02 / SWITCH

화면·음향 믹싱

화면 전환, 자막·대기 화면, 현장·온라인 오디오 구성

03 / ENCODE

인코더·전송

영상·음향 합성 신호를 플랫폼 규격에 맞춰 전송

04 / PLATFORM

YouTube·Zoom

호스트 권한, 공개 범위, 시청·질문 설정과 플랫폼 상태

05 / VIEWER

시청자 기기

다른 회선의 수신 화면·음량·지연·버퍼링 확인

행사장 화면이 정상이어도 방송이 정상이라는 뜻은 아닙니다현장 스크린에는 PPT가 나오지만 시청자에게는 이전 화면이 보이거나 영상 속 소리가 빠질 수 있습니다. 송출 시험은 현장 모니터뿐 아니라 별도 시청 환경에서 확인해야 합니다.
03 / PLATFORM OPTIONS

YouTube와 Zoom, 어떤 방식이 적합할까요?

플랫폼은 시청 방식, 접속 권한, 질문 구조, 녹화 공개 범위에 따라 결정합니다. 플랫폼별 기능과 유료 요금제·계정 조건은 변경될 수 있으므로 행사에 사용할 계정에서 실제로 확인해야 합니다.

YouTube Live

링크 중심으로 시청자를 안내하는 공개 강연·행사 중계에 활용할 수 있습니다. 공개·일부공개·비공개 등 접근 방식과 방송 기능 사용 가능 여부는 소유 계정 및 행사 설정을 검토해야 합니다.

주요 확인: 시청 대상 · 공개 여부 · 채팅·다시보기 운영

Zoom Meeting

참석자의 음성·화면 참여와 상호작용이 필요한 회의형 행사에 검토할 수 있습니다. 참가자 마이크·화면 공유 권한과 호스트·공동 호스트의 통제 범위를 확정해야 합니다.

주요 확인: 양방향 참여 · 호스트 권한 · 녹화·참가자 관리

Zoom Webinar

발표자·패널과 일반 참석자의 역할을 나누는 설명회·강연형 행사에 적합할 수 있습니다. 등록·질문·투표 등 사용할 기능은 실제 라이선스 및 설정에 따라 확인합니다.

주요 확인: 패널 권한 · 참석자 질문 · 계정 플랜
04 / NETWORK & AUDIO

회선과 음향은 무대 장비와 별개로 점검합니다

송출 장애 원인을 줄이려면 인터넷 품질, 현장 음향·송출 믹스, 원격 발표자의 반환 음성, 전원과 접근 권한을 개별 확인해야 합니다.

NETWORK 01

유선 회선과 공유 여부

행사장 업로드 품질과 회선 사용 주체를 확인합니다. 다른 참가자·대관 시설과 공유하는 회선인지, 행사 전과 본행사 시간대 모두 테스트 가능한지도 확인해야 합니다.

점검 항목: 실제 행사 시간대 · 업로드 안정성 · 장소 방화벽·접속 제한
NETWORK 02

백업 회선과 전환 조건

모바일망·별도 회선 등 대체 연결이 필요하면 실제 현장에서 연결 품질과 전환 절차를 시험합니다. 백업 회선이 있다는 사실만으로 방송 연속성이 보장되지는 않습니다.

점검 항목: 백업 연결의 실제 송출 가능 여부 · 전환 담당 · 현장 수신 상태
AUDIO 01

현장 PA와 온라인 음향

행사장 스피커는 정상인데 시청자에게 소리가 작거나 영상 재생 음성이 안 들릴 수 있습니다. 마이크·동영상·음악 소스를 송출 오디오에 각각 반영하는지 테스트합니다.

점검 항목: 오디오 인터페이스 · 출력 경로 · 음량·지연 · 모니터링
AUDIO 02

원격 발표자와 에코 방지

현장과 원격 연자가 서로 대화하는 경우 원격 음성을 행사장에 들려주면서 다시 원격으로 되돌아가는 소리는 제어해야 합니다. 반환 음성 경로와 장비 연결을 리허설에서 검증합니다.

점검 항목: 원격 연자 리턴 음성 · 에코·하울링 · 현장/온라인 Q&A
05 / REHEARSAL

최종 리허설은 실제 시청 화면까지

행사장에 도착해 장비를 연결하는 것과 온라인 방송을 안전하게 진행할 준비가 된 것은 다릅니다. 담당자를 구분한 순서로 시험합니다.

TEST 01

카메라·발표자료·영상 소스

카메라 화면, PPT, 영상 재생과 영상 속 음성이 실제 화면 구성에 반영되는지 확인합니다. 발표자의 개인 노트북이 연결되는 경우 출력 방식과 대체 입력도 확인합니다.

TEST 02

시청자 측 독립 수신 테스트

행사장 송출 컴퓨터가 아닌 별도 기기·연결에서 화면·음량·자막·영상 지연·버퍼링을 확인합니다. 시청자 측 테스트 담당자를 명확히 지정합니다.

TEST 03

실제 플랫폼 계정·공개 범위

송출 계정의 관리자 권한, 방송 예약과 공개 설정, 참가자 링크, 녹화 권한, 채팅·Q&A의 실제 동작을 확인합니다. 비공개 테스트 링크의 유출·공개 전환도 주의합니다.

TEST 04

원격 발표·질의응답 전환

현장 발표자에서 원격 발표자로 바뀔 때의 화면과 음향, 객석 질문 마이크, 원격 발표자의 재접속 절차를 실제 순서대로 시험합니다.

TEST 05

녹화·장애 대응 및 종료

송출 장애 발생 시 누가 중단·복구·공지할지 정하고, 실제 녹화본에서 영상·음향이 정상 기록되는지 확인합니다. 방송 종료 후 링크·녹화·공개 권한의 처리도 정합니다.

06 / INCIDENT RESPONSE

송출 장애는 증상별로 판단과 대응을 분리합니다

인터넷이 끊기는 상황만 문제가 아닙니다. 송출 화면·소리·원격 발표자의 연결·플랫폼 권한 문제가 발생할 때 누구에게 어떤 신호를 전달할지 정해야 합니다.

발생 상황우선 확인사전에 정할 대응·담당
온라인에서만 음성 불량현장 마이크·영상 소리의 송출 믹스, 인코더 오디오 출력, 수신 기기 음량음향 담당이 원인 구간 확인, 송출 담당이 시청자 화면 재검수
PPT 화면 전환 오류현장 발표 화면과 송출 화면의 차이, 스위처 입력, 파일 버전자료 운영 담당이 최종본 확인, 화면 담당이 대체 소스·대기 화면 전환
회선·인코더 장애회선 연결, 플랫폼 수신 상태, 인코더 전원·설정, 백업 연결 품질송출 기술 담당의 복구·대체 경로 적용, 주최 측의 계속 진행·중단 결정
원격 발표자 연결 끊김원격 발표자의 네트워크, 발표 파일 백업, 다음 발표 순서진행 담당이 승인받은 대체 순서 공유, 시청자 안내 담당이 공지
플랫폼 접속·권한 문제호스트 권한, 비공개 설정, 접속 링크·대기실, 라이선스·플랫폼 상태계정 관리자·접속 안내 담당이 문제 확인, 변경 링크·재접속 방식 공지
ILLUSTRATIVE INCIDENT

예시: 방송 도중 시청자 화면만 검게 나온다면?

다음은 실제 사고 기록이 아닌 운영 절차 예시입니다. 현장 프로젝터 화면과 온라인 시청 화면이 다른 상황을 가정합니다.

1. 장애 확인시청자 화면 모니터링 담당이 검은 화면 발생 시각·영향 범위를 전달
2. 신호 분리화면 전환 담당이 카메라·PPT·송출 인코더·플랫폼의 각 구간 상태 점검
3. 대체 화면가용한 영상 소스나 대기 화면으로 전환 가능한지 확인하고 주최 측 운영 판단을 받음
4. 안내·복구주최 측 승인에 따라 온라인 시청자에게 공지하고 화면·음향 복구를 독립 수신 환경에서 확인
07 / RECORDING & DELIVERY

라이브 송출과 녹화 납품은 별도의 작업입니다

방송이 끝나면 어떤 파일을 받을 수 있는지 먼저 합의해야 합니다. 카메라 원본과 실제 방송 화면, 발표별 편집본, 자막·썸네일 제작은 업무 범위가 다릅니다.

산출물 종류포함될 수 있는 내용계약 전 확인할 기준
송출 프로그램 녹화본온라인 방송 당시 카메라·PPT·자막이 전환된 최종 출력 영상녹화 여부, 해상도·파일 형식, 실시간 오류 포함 여부, 전달 기한
카메라별 원본카메라에서 별도로 기록한 편집 전 촬영 파일별도 녹화 장비·저장 공간·카메라별 파일 전달 범위
발표·세션별 편집본강연 또는 세션 단위로 분리하고 시작·종료를 편집한 영상분할 기준, 타이틀·자막, 편집 수준, 수정 횟수와 납기
현장 사진·결과 자료행사 전경·발표자·참석자 사진, 송출 기록과 행사 결과보고용 정보촬영 담당 범위, 사진 선정·보정, 보고서와 지표의 기준
다시보기·공개 설정방송 아카이브 링크 또는 별도 저장·배포 파일소유 계정, 공개·접근 기간, 저작권·초상권·발표자 승인 조건

10 / FAQ

행사 송출에 관해 자주 묻는 질문

YouTube와 Zoom 중 어떤 방식이 맞나요?

링크를 통해 많은 사람에게 방송을 보여주는 목적에는 YouTube Live를 검토할 수 있고, 참가자 간 상호작용이 필요한 경우 Zoom Meeting이나 Webinar를 검토할 수 있습니다. 등록·질문·공개 설정과 계정 기능을 함께 확인해야 합니다.

현장 행사와 동시에 송출할 수 있나요?

네. 현장 무대와 온라인 화면·음향을 함께 운영하는 하이브리드 송출을 협의할 수 있습니다. 행사장 음향과 인터넷, 화면·마이크 구성에 대한 사전 점검이 필요합니다.

송출 영상을 따로 녹화할 수 있나요?

네. 방송 프로그램 출력과 카메라 원본, 발표자별 편집본의 녹화·납품 범위를 따로 정할 수 있습니다. 원본 제공과 편집·자막·수정 작업은 별도 업무인지 확인해야 합니다.

행사장 인터넷만으로 라이브 송출이 가능한가요?

가능 여부는 해당 회선의 업로드 안정성, 공유 여부, 보안 정책, 실제 방송 조건에 따라 달라집니다. 현장 유선 회선을 우선 검토하고 행사 시간대에 실제 플랫폼 송출 테스트를 진행하는 것이 좋습니다.

방송 중 화면이 끊기면 송출을 유지할 수 있나요?

장애 원인과 예비 연결·대체 화면·운영 승인 체계에 따라 대응할 수 있지만 무중단을 보장할 수는 없습니다. 송출 장애 시 공지·복구·현장 진행 결정권자를 사전에 정해야 합니다.

행사 라이브 송출 견적은 어떤 기준으로 달라지나요?

화면 소스와 카메라 구성, 발표자료·자막 전환, 현장 음향, 인터넷·인코더, 플랫폼 계정, 설치·리허설·송출 시간, 녹화·편집 납품 범위에 따라 달라집니다. 장비 수량 외에 역할·시간·산출물을 함께 확인해야 합니다.
